# Magic → Avito

Проект получает мужскую одежду из открытого каталога Magic Shop, рассчитывает цену,
создаёт объявления и формирует два варианта автозагрузки:

- `output/avito_ready.xlsx` — таблица для ручной загрузки;
- `output/avito_feed.xml` — фид для автоматического обновления;
- `output/products.json` и `products.csv` — исходный каталог;
- `output/validation_report.json` — ошибки, которые нужно исправить до загрузки;
- `output/image_audit.json` — результат проверки доступности всех фотографий.

Парсер использует JSON-интерфейс каталога, получает все страницы и не запускает браузер.
В запросах есть пауза, настраиваемая в `config.yaml`.

## Быстрый запуск в Windows

1. Установите Python 3.11+ и [uv](https://docs.astral.sh/uv/).
2. Запустите `run.ps1`. При первом запуске он создаст `config.yaml`.
3. Заполните в `config.yaml` как минимум `seller.address`. Если способ связи требует
   телефона, заполните `seller.contact_phone`.
4. Запустите `run.ps1` повторно.

Командный вариант:

```powershell
uv sync
uv run magic-avito --init-config
uv run magic-avito --limit 10
uv run magic-avito
```

Код возврата `2` означает, что файлы созданы, но валидатор нашёл незаполненные
обязательные данные продавца. Смотрите `output/validation_report.json`.

## Официальный шаблон Avito

Точный набор полей зависит от категории и может меняться. Надёжный вариант:

1. В кабинете Avito откройте «Автозагрузка» → «Правила и шаблоны».
2. Выберите «Одежда, обувь, аксессуары» → мужская одежда.
3. Скачайте XLSX в `templates/avito.xlsx`.
4. Запустите:

```powershell
uv run magic-avito --template templates/avito.xlsx
```

Экспортёр находит строку заголовков, сохраняет листы и порядок колонок официального
шаблона, затем заполняет известные поля. Неизвестные поля остаются пустыми и будут видны
в отчёте Avito. Не добавляйте в официальный файл произвольные листы или столбцы.

Встроенная таблица без шаблона предназначена для подготовки данных и первичной проверки.
Перед массовой публикацией один раз прогоните файл через валидатор Avito.

## Цены

Правила задаются в `pricing.bands`. По умолчанию:

- до 5 000 ₽: +60%;
- до 10 000 ₽: +45%;
- до 20 000 ₽: +35%;
- до 40 000 ₽: +30%;
- выше: +25%.

Результат округляется вверх до цены, заканчивающейся на `990`.

## Фото

В Excel и XML записываются публичные прямые ссылки на изображения. Avito скачивает их
при обработке фида. Для локальной копии:

```powershell
uv run magic-avito --download-images
```

Файлы появятся в `output/images/<артикул>/`. Убедитесь, что поставщик разрешает
коммерческое повторное использование фотографий и характеристик.

Чтобы проверить каждую ссылку без скачивания всех файлов:

```powershell
uv run magic-avito --config config.yaml --verify-images
```

Проверка делает до трёх попыток для временных сетевых ошибок, читает сигнатуру
JPEG/PNG и автоматически убирает из XLSX/XML недоступные ссылки. Если у товара
не осталось ни одной рабочей фотографии, объявление не попадает в выгрузку, а его
Id записывается в `output/image_audit.json` и предупреждения отчёта валидации.
API каталога также автоматически повторяется при таймаутах, ограничении частоты и
временных ошибках сервера.

Если API временно недоступен, выгрузку можно воспроизводимо пересобрать из последнего
сохранённого снимка каталога:

```powershell
uv run magic-avito --config config.yaml --cached-products output/products.json --verify-images
```

В консольном результате `source_mode` явно покажет использование кэша.

Если фотохост недоступен целиком, можно повторно применить последний завершённый
аудит (не частично оборванный файл):

```powershell
uv run magic-avito --config config.yaml --cached-products output/products.json `
  --verify-images --cached-image-audit output/image_audit.json
```

Поле `audit_mode` в отчёте явно показывает, что использован сохранённый аудит.
Перед применением программа сверяет количество URL и SHA-256 отпечаток всего набора,
поэтому аудит от другого каталога использовать нельзя.

Парсер передаёт все фотографии товара в исходном порядке, но не больше лимита
`export.max_images` (по умолчанию 10). Первая ссылка становится обложкой объявления.

## Описания с OpenAI

Без ключа проект создаёт уникальные описания из фактических характеристик товара и удаляет
упоминания поставщика. AI-режим использует официальный Python SDK и Responses API.
[Официальный пример OpenAI Responses API](https://developers.openai.com/api/docs/quickstart#install-the-openai-sdk-and-run-an-api-call)

```powershell
uv sync --extra ai
$env:OPENAI_API_KEY = "ваш ключ"
uv run magic-avito --ai
```

Модель меняется через `OPENAI_MODEL` или `description.model`. Не сохраняйте ключ в Git.

## Автоматическая публикация

Проект не нажимает кнопки в аккаунте и не обходит защиту Avito. Используется официальный
механизм автозагрузки:

1. Сформируйте `avito_feed.xml`.
2. Разместите файл по постоянному публичному HTTPS-адресу.
3. В кабинете Avito создайте автозагрузку и укажите этот URL.
4. Сначала включите тестовый лимит и проверьте отчёт обработки.

В репозитории есть ручной GitHub Actions workflow. Он формирует выгрузку и прикладывает её
как artifact. Для полностью автоматической публикации понадобится отдельный публичный хостинг
фида и секреты продавца; не публикуйте телефон или адрес в открытом репозитории.

## Важные ограничения

- Структура категорий Avito меняется; официальный шаблон имеет приоритет над встроенным.
- Адрес, телефон и настройки тарифа нельзя определить по каталогу поставщика.
- Публикация и платные услуги Avito остаются под контролем владельца аккаунта.
- Для фото и исходных характеристик нужны права на коммерческое использование.
